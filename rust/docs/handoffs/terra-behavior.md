# Social and behavior handoff

- `SocialCoordinator.frequency` defaults to 50. Set from settings each update; 0 suppresses autonomous starts only, manual requests still work. The factor scales social cooldowns and tower invitation intervals. Existing active interactions continue.
- Manual requests now explain a refusal once, after the request expires or the selected pet is unavailable: self busy, friends busy, other support, insufficient room, or specific tower ceiling/room. Selection of a busy tower requester no longer silently substitutes another pet. Successful tag/leapfrog can end with one quiet celebration.
- Leapfrog checks a third pet's current position at each landing before launching. This prevents the reproduced case where a 1.5-scale jumper struck an uninvolved friend. If a friend occupies all viable landings later, the game cancels cleanly. This is a conservative snapshot, not prediction of moving third parties through the entire arc.
- `five_pet_integration` exercises contacts, behavior, social, a window, taskbar-height change, both games, and 0.75/1.0/1.5 scales. The moving taskbar/window changes occur after the game starts, and the test checks completion and finite state. A separate regression reproduces the crowded landing. Existing `leapfrog_scale_regression` covers 2–10 jumps with contacts and mixed scales.
- Validation: `cargo +stable-x86_64-pc-windows-gnu test --test five_pet_integration --test social_play_regression --test group_tower_regression --test leapfrog_scale_regression --lib` (119 library tests passed, 1 MSI test ignored; focused integrations passed); `cargo +stable-x86_64-pc-windows-gnu fmt`; `cargo +stable-x86_64-pc-windows-gnu clippy --all-targets -- -D warnings` passed. The landing guard was added after the combined run; `five_pet_integration`, `social_play_regression`, and `leapfrog_scale_regression` were rerun after it, followed by clippy.
- No native desktop interaction, settings wiring, installer, version, or release work. Existing unrelated local modifications to uninstall scripts were untouched.

## Approach follow-up

Manual selected-pet invitations reserve a same-support friend and walk the selected pet to a gap within the chosen game's distance range, at bounded speed. The approach checks third-party occupancy and ends on command, drag, disappearing support, blockage, replacement request or 12-second timeout. Active reservations are cleaned without overriding an interrupting command. Explicit refusal events bypass only the identical-event speech cooldown; this is scoped to manual refusal paths. Tests `social_approach_regression` run contacts, behavior and social together at three scales and exercise interruption, window removal, blocked path, timeout and rapid repeated refusals. fmt and clippy --all-targets -D warnings passed. Path occupancy is a live snapshot; it is not a prediction of future motion.
