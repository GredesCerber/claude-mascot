# UI perches: implementation handoff

`UiPerchMonitor::new()` starts one detached, disabled-by-default worker. Set `set_enabled(settings.ui_perches)` when the preference changes and assign `world.ui_surfaces = monitor.snapshot(&world)` after the current window snapshot. The latter only copies bounded cached geometry and synchronously filters by active owner, clipping and external window occlusion. COM is never called on the game thread. A stuck provider does not block shutdown and its snapshot expires after 1.5 s.

The worker reads control type, runtime ID, bounding rectangle, offscreen and password flags. It does not read text or invoke controls. It observes only the active non-fullscreen owner, traverses at most 256 nodes/depth 8, emits up to 32 stable Edit/Separator rectangles at 2 Hz, and rejects ambiguous IDs. Disappearance, owner change, or a large jump creates a new session identity. Gradual movement up to 20 px per observation preserves identity. This does not guarantee detection of provider-side virtualization that reuses an ID in place; rows and messages are not collected.

`World.ui_surfaces` is separate from windows/icons. A falling pet can land when its entire width fits and owner headroom is sufficient; it follows small movements and falls from its real position when its support is lost or shrinks. User dragging wins. UI surfaces do not participate in social actions. A rare autonomous jump can start from the floor when the active owner reaches it and the whole body and sampled ballistic corridor fit inside that owner. Higher windows block the route; known UI surfaces are landing edges, not walls. The 0.22 s crouch is cancelled if the target disappears or moves; during flight, loss ends route ownership without teleporting or stopping the real physics. This deliberately narrow scenario does not cover general UI navigation. No Pane support is included: generic panes often cover huge interactive regions and cannot be treated safely as perches without more filtering.

Limitations: clipping is conservative ancestor bounding-box containment, not complete native control occlusion; same-application overlays can escape detection. No testing on real external UIA providers, mixed DPI, scrolling, Alt+Tab, or drag FPS was performed. Test on real applications before describing broad support. No name/value/text or user config is persisted. Do not enable by default. A blocking provider could occupy the worker indefinitely; the feature then stays unavailable until restart.
